# 鲜花遗留边界说明

## 1. 当前判断

`ruoyi-flower` 不应再被视为“标准商城模块”，而应视为：

- 鲜花遗留能力
- 商城基础能力
- 扩展功能

三者混合后的历史模块。

## 2. 当前已识别的混合内容

### 可归入商城主干的内容

- 商品
- 分类
- SKU
- 购物车
- 订单
- 支付
- 退款
- 基础配送
- 会员
- 积分
- 优惠券基础能力

### 明显超出本次主干范围的内容

- 课程
- 社区/花友圈
- 鲜花专属配送温区、盒型、模板扩展
- 会员推广计划/推广记录
- 鲜花专属字段和冷链语义

### 待确认内容

- 积分商品与积分订单是否保留为标准商城积分兑换能力
- 配送规则中哪些是通用物流，哪些是鲜花专属
- 某些营销能力是否可收敛为标准优惠活动能力

## 3. 当前命名问题

在 `ruoyi-flower` 中同时存在：

- `flower`
- `flowerapplet`
- `flowerApplet`
- `flowerPc`
- `Folwer`

这会带来：

- 搜索困难
- 自动化改造困难
- AI 理解困难
- 领域边界难以澄清

## 4. 当前治理策略

本阶段不直接做大规模代码改名。

先做：

- 文档定义边界
- 标记保留/剥离/待确认范围
- 明确未来命名规则

后做：

- 逐域重构
- 路径规范化
- DTO / Service / Domain 命名清理

## 5. 对 AI 辅助改造的影响

如果不先澄清这一边界，AI 会很难区分：

- 哪些接口是商城核心能力
- 哪些属于鲜花特化能力
- 哪些是以后应停止扩展的历史模块

因此本文件是 AI Harness 化治理的基础文档之一。
