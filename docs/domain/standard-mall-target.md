# 标准商城目标说明

## 1. 目标系统定义

当前项目的目标不是继续演进鲜花垂直商城，而是清洗为：

- 单商户标准商城系统

目标终态：

- 网页后台管理端
- 微信小程序 C 端

不纳入本次主干的内容：

- 多商户平台
- 商家入驻
- 平台结算和抽佣
- 课程模块
- 社区模块
- 鲜花专属冷链主链路
- 花券、分账、推广返利作为主链路能力

## 2. 目标核心能力域

- 用户体系
- 权限体系
- 商品体系
- 订单体系
- 支付体系
- 物流体系
- 会员体系
- 积分体系

## 3. 后台管理端目标能力

- 商品管理
- 分类管理
- SKU / 规格管理
- 库存管理
- 订单管理
- 发货与物流管理
- 用户管理
- 会员管理
- 积分规则管理
- 优惠券/营销基础管理
- 后台账号、角色、权限管理
- 基础系统配置管理

## 4. 微信小程序目标能力

- 首页/分类/搜索
- 商品详情
- 购物车
- 下单
- 微信支付
- 我的订单
- 物流查询
- 售后申请基础版
- 会员中心
- 积分获取与使用
- 优惠券领取与使用

## 5. 当前改造原则

- 将现有系统视为“带鲜花遗留的商城后端基座”
- 保留底座，不继续放大 `ruoyi-flower` 的历史坏边界
- 商品中心向标准 SPU / SKU / 分类 / 属性模型演进
- 订单、支付、物流从鲜花专属流程中解耦
- 会员和积分保留，但与返利/分账主链路解绑
- 新增结构不再使用 `flower` / `folwer` 作为核心业务命名

## 6. 当前文档用途

本文件是后续评估、设计和改造的目标约束说明。

后续如出现以下情况，应以本文件为准进行判断：

- 某功能是否属于商城主干
- 某遗留领域是否应保留
- 某命名是否应继续沿用
- 某模块是否应继续扩展
