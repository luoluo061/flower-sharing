# 环境前置条件

本文件用于定义当前仓库可构建、可运行、可验证所需的最小环境要求。

目标：

- 明确哪些属于必备环境
- 区分“仓库问题”和“机器环境问题”
- 为后续引入更稳定的构建入口提供依据

## 1. 当前最小环境要求

### JDK

- 版本：17
- 用途：编译、运行、打包后的 Jar 启动

当前会话验证结果：

- `java` 已可用

### Maven

- 建议版本：3.9+
- 用途：编译、打包、运行现有测试

当前会话验证结果：

- `mvn` 不在 PATH 中
- 仓库未提供 Maven Wrapper

结论：

- 当前构建验证受限于本机未安装或未配置 Maven

### 数据库

- 类型：MySQL 8
- 用途：主应用、商城业务数据

说明：

- 当前 YAML 中存在多套数据库连接配置和历史地址
- 真实生效配置需后续进一步确认

### Redis

- 类型：Redis 6+
- 用途：缓存、分布式能力、部分业务链路

## 2. 扩展服务相关环境

### 监控中心

- 依赖：JDK 17
- 建议具备：可访问主应用

### SnailJob 服务端

- 依赖：JDK 17、MySQL
- 网络关注点：
  - HTTP 端口 `8800`
  - Netty 端口 `17888`

## 3. Docker 相关环境

如果使用 Docker 路线，还需要：

- Docker
- Docker Compose

说明：

- 当前仓库已存在 3 个 Dockerfile 和多份 compose 文件
- 但具体哪份是正式入口仍需以后续部署现状为准

## 4. 当前工程问题

### 缺少 Maven Wrapper

当前仓库没有：

- `mvnw`
- `mvnw.cmd`
- `.mvn/`

这意味着：

- 构建能力依赖开发机本地 Maven 环境
- 不同机器之间的一致性较差

### 本地运行入口不统一

当前存在：

- Jar 运行方式
- Dockerfile
- Docker Compose
- `script/bin` 脚本
- `.run/` Docker build 配置

但它们并未形成统一、标准、明确的优先级说明。该问题已在当前文档体系中开始收敛。

## 5. 后续建议

### 低风险建议

- 在 README 和 docs 中持续显式说明环境要求
- 将“环境缺失”与“项目失败”区分记录

### 中风险建议

- 评估引入 Maven Wrapper
- 统一本地开发和 CI 的构建入口

## 6. 使用原则

当验证失败时，先判断属于哪一类：

1. 本机环境问题
2. 外部依赖缺失
3. 项目构建问题
4. 项目业务回归问题

只有在第 1、2 类排除后，才把失败归因到项目本身。
