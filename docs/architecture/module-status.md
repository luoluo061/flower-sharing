# 模块启用状态

本文件用于描述当前仓库中各模块的“目录存在状态”和“构建启用状态”。

目标：

- 避免把“目录存在”误判为“当前系统正在使用”
- 为后续遗留模块治理和裁剪提供依据

## 1. 根聚合模块

当前根 `pom.xml` 聚合：

- `ruoyi-admin`
- `ruoyi-common`
- `ruoyi-extend`
- `ruoyi-modules`

这些均为当前构建树的一部分。

## 2. `ruoyi-common` 状态

`ruoyi-common` 下各公共能力模块当前均在聚合内，视为：

- 当前启用基础模块

说明：

- 即使部分能力未被主业务直接使用，也仍属于底座公共能力层

## 3. `ruoyi-extend` 状态

当前启用：

- `ruoyi-monitor-admin`
- `ruoyi-snailjob-server`

说明：

- 两者都在 `ruoyi-extend/pom.xml` 中启用
- 两者也都有独立启动类和 Dockerfile
- 视为当前独立扩展服务

## 4. `ruoyi-modules` 状态

### 当前在聚合中启用

- `ruoyi-demo`
- `ruoyi-generator`
- `ruoyi-system`
- `ruoyi-flower`

### 当前目录存在但未在聚合中启用

- `ruoyi-job`
- `ruoyi-workflow`

结论：

- `ruoyi-job` 和 `ruoyi-workflow` 不应被默认视为当前运行系统的一部分
- 但也不能在未确认前直接删除

## 5. 业务主模块状态

### `ruoyi-flower`

当前判断：

- 当前主业务模块
- 同时承载商城核心域与鲜花遗留域
- 后续治理重点对象

### `ruoyi-demo`

当前判断：

- 底座演示模块
- 当前仍在聚合和主应用依赖中
- 后续需确认是否保留到商城基线中

### `ruoyi-generator`

当前判断：

- 代码生成模块
- 当前仍在聚合和主应用依赖中
- 属于基础平台能力，不是商城核心域

### `ruoyi-system`

当前判断：

- 系统管理与权限能力核心模块
- 应作为底座保留

## 6. 当前治理建议

### 低风险

- 先在文档中明确“启用 / 未启用 / 待确认”状态
- 后续改造中按此状态判断影响范围

### 中风险

- 视后续验证情况，评估是否从主应用依赖中收缩 `ruoyi-demo`
- 评估 `ruoyi-job`、`ruoyi-workflow` 是否退出当前仓库主线认知

## 7. 使用原则

后续讨论模块时，默认使用以下术语：

- 启用模块：在当前聚合中参与构建
- 遗留目录模块：目录存在，但当前未参与聚合
- 主业务模块：当前运行系统的核心业务模块
- 底座模块：基础平台与通用能力模块
