# 脚本目录清单

## 1. 目录结构

`script/` 当前包含：

- `bin/`
- `bpmn/`
- `docker/`
- `sql/`

## 2. `bin/` 目录

### `script/bin/ry.bat`

- 类型：Windows 启动脚本
- 目标：`ruoyi-admin.jar`
- 支持动作：启动、停止、重启、状态
- 实现方式：`jps` + `taskkill` + `javaw`

问题：

- 仅支持主应用
- 未覆盖监控中心和 SnailJob
- 未区分环境
- 不适合作为多服务标准管理脚本

### `script/bin/ry.sh`

- 类型：Linux 启动脚本
- 目标：`ruoyi-admin.jar`
- 支持动作：启动、停止、重启、状态
- 实现方式：`ps/grep/kill` + `nohup java`

问题：

- 仅支持主应用
- `LOG_PATH` 定义后未真正使用
- 未体现服务依赖关系
- 适合作为历史脚本参考，不足以承担标准部署入口

## 3. `bpmn/` 目录

- 当前包含流程资源压缩包
- 结合根模块现状看，工作流模块并未纳入当前聚合构建
- 该目录暂不删除，先标记为“遗留候选资源”

## 4. `sql/` 目录

- 含 MySQL / Oracle / PostgreSQL / SQL Server 初始化脚本与升级脚本
- 当前主应用实际依赖 MySQL
- 其余数据库脚本多为底座遗留，是否保留待后续确认

## 5. 后续治理建议

- 先给脚本加说明，不急于重写
- 后续统一定义多服务启动命令和顺序
- 如保留脚本，建议拆分为：
  - 主应用
  - 监控中心
  - SnailJob
  - Docker 辅助脚本

## 6. 待确认事项

- 当前生产是否仍使用 `script/bin` 下脚本
- 是否存在外部运维脚本未纳入仓库
