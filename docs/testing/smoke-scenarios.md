# 关键链路冒烟方案

本文件定义当前项目最值得优先保护的关键链路。

目标：

- 为后续人工验证提供固定顺序
- 为后续接口脚本化提供候选场景
- 让 AI 改动时知道最小必回归范围

范围说明：

- 本文档优先覆盖商城主线冒烟场景
- `ruoyi-demo` 与 `ruoyi-generator` 当前不作为默认冒烟主线
- 当前接口暴露面基线见 `docs/architecture/api-surface.md`

## 1. 场景 A：主应用基础可用

前置：

- 主应用启动成功

检查项：

- `/swagger-ui.html` 可访问
- `/v3/api-docs` 可访问
- 登录接口可访问

价值：

- 验证基础 Web、权限、接口文档、主配置没有整体损坏

## 2. 场景 B：后台商品域基础可用

建议检查：

- 商品列表接口可访问
- 商品详情接口可访问
- 分类接口可访问
- SKU 相关接口可访问

价值：

- 商品中心是后续标准商城清洗的核心域之一

## 3. 场景 C：后台订单域基础可用

建议检查：

- 订单列表接口可访问
- 订单详情接口可访问
- 退款接口可访问
- 发货或配送相关接口可访问

价值：

- 订单、支付、物流是本次重构最敏感区域

## 4. 场景 D：小程序商品与下单链路

建议检查：

- 小程序商品列表
- 小程序商品详情
- 购物车相关接口
- 下单相关接口

价值：

- 这是最接近 C 端核心链路的最小验证组合

## 5. 场景 E：支付回调链路

建议检查：

- `/wxpayback/*` 路径仍可访问
- 支付回调处理类未被误伤
- 支付成功后的订单流转逻辑仍可进入

说明：

- 支付链路不建议在未准备好环境前直接做真实支付验证
- 现阶段先保证路径、处理器和业务入口不被改坏

## 6. 场景 F：监控与扩展服务

建议检查：

- `ruoyi-monitor-admin` 可启动
- `ruoyi-snailjob-server` 可启动
- 主应用监控接入配置未被破坏

## 7. 优先级建议

每次改动至少覆盖：

1. 场景 A

涉及商品、订单、支付、物流代码时再增加：

1. 场景 B
2. 场景 C
3. 场景 D

涉及支付时额外增加：

1. 场景 E

涉及部署、配置、监控、任务服务时额外增加：

1. 场景 F
